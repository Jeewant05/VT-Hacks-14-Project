# Coordination workspace

Mode: Operate. Extend the existing light and green visual system using the approved single-workspace outline; code-led implementation of a specified application structure, without replacing its visual identity.

## First viewport

A narrow repository sidebar, compact repository breadcrumb and environment strip, objective title and acceptance checklist, a four-step state indicator, two connected agent workstreams, and a right-hand event timeline. No marketing hero. At conflict, the contract comparison replaces the quiet prompt below the agent pair and becomes the primary focus.

## Signature interaction

The user accepts the Databricks-backed contract correction in the labeled simulation. Field names change from accessToken/profile to token/user, with brief state feedback. The UI explicitly waits for redeclaration, then for submitted ChangeSets; accepting alone never completes review.

## Boundaries

The current HTTP API is read-only. Demo state is local and isolated from backend state. Repository file previews are illustrative manifests and excerpts, not actual Git diffs. Identity evidence, decisions, and test results identify their source. Keep real provider integration and coordinator endpoints outside this frontend milestone.

## Composition and behavior

- Desktop: 216px sidebar, flexible main workspace, 300px activity rail; collapse the rail below content on compact desktop and stack the agent cards on mobile.
- Sidebar destinations: Workspace, Repository, Project memory, Integrations. Workspace tabs: Workstreams, Changes, Convergence.
- One green primary action per phase. Muted controls remain available for reset and evidence inspection. Reset requires confirmation only after progress exists.
- Drawer for secondary evidence, with focus restoration and Escape support. Keyboard-accessible tabs and navigation; reduced-motion support; visible focus and status announcements.
- Verification and memory source labels remain visible in all views. Never use a green live-integration badge for demo data.

## Validation

Test reducer transitions and completion gates, then inspect desktop/mobile, full demo, file inspection, reset, backend-disconnected state, and keyboard overlay behavior. Record remaining sponsor dependencies in the handoff.
